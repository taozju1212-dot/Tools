## 六、系统评审

### P-TEST-02 功能审查 — 项目整体功能评审

**使用场景**：阶段性对软件进行功能完整性、交互合理性、核心使用场景覆盖度的系统评审

**提示词**：
```
你现在不是开发者，而是一个”资深软件评审专家（产品 + UX + 工业设备方向）”。

请对当前项目进行一次【系统级评审（UX Audit + 功能评估 + 交互评估）】。

【输入信息】
- PRD.md（产品需求文档）
- 当前代码实现（fa120_log_parser.py）
- 用户使用场景：售后人员根据客户反馈的照片（含错误报警码和结果编号），
  快速定位该错误发生时的前后动作，以及该测试样本完整的动作执行流

【评审目标】
评估这个软件是否做到：
1. 易用高效 — 关键操作路径短，不需要学习成本
2. 快速定位 — 从报警码/样本编号出发，能在 30 秒内找到对应动作上下文
3. 联动清晰 — 报警、样本动作、日志原始内容三者之间的关联是否直观

【输出要求】
1. 不要泛泛而谈，必须具体到界面元素或代码功能
2. 每个问题必须包含：
   - 问题描述（具体在哪里、什么情况触发）
   - 影响（对哪类用户、造成什么障碍）
   - 修改建议（可操作的改进方案）
3. 优先指出”异常 → 样本 → 动作 → 原始日志”联动链路中的断点
4. 按优先级排列（高 / 中 / 低）
```

**目标输出**：结构化评审报告，含问题列表（优先级 + 问题 + 影响 + 建议）



## 七、提示词编写规范

> 供编写新提示词时参考

1. **明确角色**：说明 AI 扮演的角色（如"作为 Python 专家"）
2. **提供上下文**：描述项目背景、技术栈、约束条件
3. **明确输出格式**：说明期望的输出形式（代码、文档、列表等）
4. **限定范围**：避免过于开放的描述，聚焦在具体问题上
5. **附上示例**：复杂需求尽量给出输入/输出示例
